# Crystal.Control.Web 信息架构与高保真原型

> 最后更新：2026-11-10
> 状态：生效（内容只读 + 账号生命周期联调版）

## 1. 目标与边界

`Crystal.Control.Web` 是管理后台前端，不是玩家游戏客户端或玩家门户。目标用户是版本作者、发布审核、运营/GM、财务、审计和平台管理员。

本原型用于验证：

- 一级功能域与二级页面是否覆盖内容生产、发布、区服、运营、交易和安全闭环。
- 后台版式、导航密度、详情抽屉、审批弹窗和移动端降级是否可用。
- 高风险操作是否具有明确的确认、原因、审批和审计入口。
- 哪些页面可以在 M1 先做只读版本，哪些依赖 M2 以后的写入/发布 API。

当前版本已接入真实账号登录、JWT/刷新令牌、内容总览、导入批次、10 类 MirDB 内容只读查询、账号生命周期、角色和审计查询，并按权限点过滤导航、直达路由和页面动作。内容写入/发布、文件上传、GM、支付和审批仍为前端模拟；API 不可用时保留演示模式。

### 1.1 实时联调边界

| 能力 | 数据来源 | 权限 |
| --- | --- | --- |
| 登录、刷新、登出、自助改密、当前身份 | `POST /api/v1/auth/login`、`/auth/refresh`、`/auth/logout`、`/auth/change-password`、`GET /auth/me` | 管理端账号 |
| 内容总览与实体计数 | `GET /api/v1/import-runs`、`/import-runs/{id}/content-types` | `content:read` |
| 内容库分页、搜索、详情 | `GET /api/v1/content/{entityType}` | `content:read` |
| 账号列表 | `GET /api/v1/accounts?limit=200` | `account:read` |
| 账号生命周期 | `POST /accounts`、`/accounts/{id}/status`、`/accounts/{id}/password-reset`、`PUT /accounts/{id}/roles` | `account:write` |
| 角色与权限矩阵 | `GET /api/v1/roles` | `role:read` |
| 审计事件与 CSV 导出 | `GET /api/v1/audit/events`；浏览器内导出当前查询结果 | `audit:read` |

前端通过 `?api=http://127.0.0.1:5080` 指定 API 地址。API 使用受控 CORS 允许静态站点来源；JWT 仅保存在 `sessionStorage`，访问令牌过期前自动刷新并轮换刷新令牌。

实时模式下，侧栏、全局搜索和直达路由都根据 JWT 中的权限点判定访问资格；无权限页面显示 403 空状态，不加载或回退业务样本。服务端权限策略仍是最终授权边界，前端过滤只用于减少误操作和错误请求。审计 CSV 导出仅覆盖当前已加载查询结果（最多 100 条），不是服务端异步导出任务。

## 4. 页面骨架

后台统一采用三层骨架：

```text
左侧主导航
  └── 按一级功能域分组，二级页面可折叠
顶部上下文栏
  └── 面包屑、全局搜索、通知、帮助、账号
主内容区
  └── 页面标题与动作
  └── KPI / 筛选 / 表格 / 详情 / 时间线
```

高频页面使用“列表 + 固定侧栏”结构：

- 左侧是主任务：内容表、区服表、玩家表、订单表或审批列表。
- 右侧是上下文：批次、版本、校验、健康、限额、状态机或规则。
- 详情使用右侧抽屉，避免离开当前列表丢失筛选和分页上下文。

| 闭环 | 页面链路 |
| --- | --- |
| 内容生产与发布 | 内容库 → 校验 → 导入批次/版本上下文 → 发布中心 → 区服加载 → 回滚 |
| 世界关系闭环 | 地图层 → 入口/出口坐标 → 刷怪点 → 怪物 → 掉落组 → 装备 → 关系校验 → 发布门禁 |
| 开区 | 开区模板 → 新区任务 → Agent 注册 → 健康门禁 → 开放登录 |
| GM | GM 工作台 → 原因与目标 → 风险校验 → 审批 → 区服命令 → 审计 |
| 支付 | 订单 → 支付回调 → Outbox → 区服发货 → 对账 → 差异处理 |
| 合区 | 新建任务 → 预检 → 冻结 → 备份 → 映射 → 迁移 → 校验 → 切换 → 回滚窗口 |
| 权限 | 管理账号 → 角色权限 → 登录/MFA → 会话 → 审计与告警 |

## 6. 世界关系模型

后台不把地图、怪物、掉落和装备当成四张孤立表，而是按运行时语义建立可校验关系。世界关系图谱是跨 13 类内容域的关系视图，不是第 14 类内容域。

```text
地图层（主城 / 野外 / 1F / 2F / 3F / Boss 房 / 攻城地图）
  → 入口与出口坐标（双向成对）
  → 刷怪点（地图 + 坐标 + 怪物 + 数量 + 半径 + 固定延迟 + 随机延迟，可多点）
  → 怪物（同图多种怪物；地图总量 = 各刷怪点数量之和）
  → 掉落组（独立概率 / 必掉组 / 地图组 / 活动组）
  → 物品或装备（概率、数量、稀有度）
```

同时保留反向查询：

```text
装备 → 掉落组 → 怪物 → 刷怪点 → 地图 → 坐标 / 刷新时间
```

### 6.1 关系字段

| 对象 | 原型字段 | 设计说明 |
| --- | --- | --- |
| 地图层 | 地图键、地图组、层级、尺寸、地形、阻挡文件、安全区、状态 | 一层、二层、Boss 房是独立地图，不是同一张地图上的楼层标签 |
| 传送门 | 来源/目标地图、来源/目标坐标、类型、触发方式、是否踩点移动、状态 | 楼梯、洞口、Boss 门、NPC 传送和地图边界统一建模；双向入口必须成对 |
| 刷怪点 | 地图、怪物、x/y、数量、半径、固定延迟、随机延迟、方向、路线、是否保存刷新时间 | 决定怪物在哪刷、刷几只、多久刷一次和巡逻范围；一张地图可配置多个刷怪点 |
| 地图刷怪汇总（页面派生） | 怪物种类、怪物总量、刷怪点数、Boss 点数、各怪物数量与占比 | 从所有刷怪点实时加总，用于地图容量、经验产出和经济影响分析 |
| NPC | NPC 键、地图、x/y、朝向、职能、脚本、状态 | 商店、仓库、任务、传送和行会入口都依赖坐标与脚本引用 |
| 掉落组 | 怪物、模式、期望产出、金币范围、物品条目、概率、数量、分组 | 一个怪物可关联多个掉落组，装备必须能反查来源 |
| 在线人物 | 角色、地图、x/y、朝向、状态 | 用于 GM 定位、卡点排查、异常行为和地图热点分析 |

### 6.2 页面联动

- 地图拓扑页展示地图组层级链路和坐标画布，刷怪点、Boss、NPC、传送门和人物坐标使用不同标记。
- 地图页先按怪物种类汇总“几种、每只多少、占比、几个刷新点”，再展开每个刷怪点的坐标、数量、固定延迟和随机延迟；同一怪物可以多点刷新。
- 点击地图刷怪点可直接打开刷新点详情，继续跳到怪物和掉落组；点击 NPC 可打开 NPC 详情。
- 世界关系图谱支持祖玛教主、赤月恶魔、白野猪、沃玛教主等典型玩法链切换，并展示装备产出反查。
- 物品详情展示来源怪物、掉落组、地图坐标和概率；怪物详情展示所有刷新点、坐标、刷新间隔和掉落组。
- GM 工作台展示在线人物当前地图、坐标和朝向，并可直接跳转到地图定位。

### 6.3 发布门禁

- 入口和出口坐标双向存在，目标地图和目标坐标均有效。
- 地图坐标在尺寸边界内，刷怪半径不从地图边界溢出，NPC 不与阻挡或出生点冲突。
- 每个刷怪点的数量、刷新间隔和地图怪物总量必须在容量与性能预算内，避免同图无限叠加怪物。
- 刷怪点引用的怪物存在，怪物引用的掉落组存在，掉落组引用的物品或装备存在且未归档。
- 高价值掉落必须展示概率、数量、期望产出和金币范围，支持经济影响评审。
- 地图、阻挡文件、怪物、掉落组和装备资源必须处于同一可发布快照，资源哈希一致并完成签名。
- 关系不完整时阻断发布，不能只在页面显示 warning。

## 7. 高风险交互

以下操作必须有独立确认弹窗、操作原因和审批入口：

- 发布和回滚内容版本。
- 开区后的维护、关闭和内容版本切换。
- 批量发放物品、金币和补偿邮件。
- 封禁、退款、合区冻结/切换。
- 权限调整、密钥轮换、数据库迁移演练。

原型中的确认弹窗统一展示：

- 操作对象和影响范围。
- 风险说明。
- 操作原因输入。
- 审批/二次确认按钮。
- 审计提示。
