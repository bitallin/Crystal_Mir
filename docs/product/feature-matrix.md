# 需求能力矩阵

> 最后更新：2026-11-13
> 状态：生效

## 1. 说明

本表把需求中的“所有内容都放到后台”拆成可实施的能力项。状态基于当前代码事实，不代表最终承诺；里程碑见 `docs/roadmap/milestones.md`。

| 能力 | 当前基础 | 目标能力 | 关键工作 | 里程碑 |
| --- | --- | --- | --- | --- |
| 后台控制台 | `Crystal.Control.Api` 内容只读、账号/JWT/RBAC/审计和账号生命周期已建立；`Crystal.Control.Web` 已有可联调后台 | 多角色 Web 控制台 | 登录、RBAC、审计、导航、任务中心、内容写入/发布 | M1/M2 |
| 内容版本与发布 | 从导入批次创建不可变 release、校验/编译/ECDSA 签名/发布 API 已建立；可编辑草稿和回滚未实现 | 草稿、校验、发布、灰度、回滚 | 内容 schema、发布包、签名、版本快照 | M1/M2 |
| NPC/对话/商店 | `NPCInfo` + 文本 DSL，约 191 条命令 | 可视化脚本编辑、校验、模拟、热重载 | DSL AST、编辑器、引用检查、脚本 VM | M2/M6 |

## 2. 优先级

### P0：没有就无法形成闭环

- 后台控制台、内容版本与发布。
- 物品、怪物、地图元数据、NPC、掉落、技能、商城。
- 客户端热更新、服务端内容热重载。
- 基础 GM、监控、备份。

### P1：生产运营必需

- 开区编排、合区、充值、审计、告警、回滚。
- 素材管线、地图编辑集成、NPC 可视化脚本。
- 称号、回收、内挂、自动拾取、爆率模拟。

### P2：通用化和差异化

- 活动 DSL/Lua、AI 脚本、插件、UI 主题、玩法规则。
- 多版本模板、多租户、SDK、生态。

## 3. 口径

- “后台可配置”不等于“后台可写任意逻辑”。行为逻辑必须走脚本/插件，并有沙箱和版本。
- “热更新”必须区分客户端资源、服务端内容、协议和数据库 schema，四者不能混为一谈。
- “合区”必须先从 ID、名称和引用模型开始设计，不能等到运营阶段再补。
