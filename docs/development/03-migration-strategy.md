# 迁移策略

> 最后更新：2026-11-11
> 状态：生效

## 1. 原则

- 保留现有游戏行为，先兼容再替换。
- 每一步都可运行、可验证、可回滚。
- 不在迁移期间同时重构游戏逻辑。
- 数据迁移和架构迁移分开提交。

## 2. 阶段

### 阶段 A：基线冻结

- 记录当前构建方式、数据库版本、配置和资源。
- 准备标准 `Server.MirDB` 和客户端资源。
- 建立黄金样本测试。

### 阶段 B：内容读取抽象

- 定义 `IContentSnapshotProvider`。
- 用现有二进制加载实现第一个 provider。
- `Envir` 改为通过 provider 读取内容，行为不变。

### 阶段 C：PostgreSQL 导入与二进制导出（已完成初版）

- 已实现 `tools/Crystal.LegacyImporter`，读取现有 `ItemInfo`、`MonsterInfo`、`MapInfo` 等构造器。
- 已生成 JSONL 快照并写入 `content_entity`。
- 黄金样本导入 9,793 个核心实体（含 59 个 Buff），使用测试内容根额外导入掉落、配方、NPC 脚本和资源元数据后为 9,797 个实体，结果可重复。
- 已实现 `LegacyBinaryExporter` v1：按 `SaveDB()` 顺序写出 `Version=117` 数据库，使用临时文件
  和原子替换，并通过 `LoadDB()` 冷回读比较实体语义哈希。
- 黄金样本导出两次字节一致；导出库重新生成的快照与源库实体文件逐字节一致。
- 已实现从 JSONL 快照和 PostgreSQL 最新导入批次重建旧实体后导出；黄金样本三条路径输出逐字节一致。
- 脚本导入原文、静态引用、AST 和编译校验结果；`Maps` 与 `Envir/Previews` 导入资源元数据，地图还解析尺寸和阻挡，但不复制二进制。
- 内容快照支持 ECDSA P-256 签名和验签，签名不改变实体哈希、`contentHash` 或旧二进制重建结果。
- 待完成：KMS/HSM 托管签名、发布审批与 Agent 强制验签、图库/音效等其他资源服务、内容写入/发布 API 和 PostgreSQL 16 staging 演练。

### 阶段 D：双读验证

- 区服可切换二进制或 PostgreSQL 来源。
- 同一版本分别启动，比较实体数量、索引、属性和关键计算结果。
- 记录差异，修复映射。

### 阶段 E：控制面接管

- 后台编辑写入 PostgreSQL。
- 发布内容包，区服消费。
- 二进制数据库只作为导出/回滚格式。

### 阶段 F：移除旧路径

- 稳定运行一个版本周期后，默认禁用二进制加载。
- 保留导出工具和迁移文档。
- 删除 `Server.MirForms` 中的编辑职责，只保留必要的开发工具。

## 3. 二进制兼容

- 保留 `Envir.Version=117`、`MinVersion=60` 的读取逻辑。
- 新字段写入 `legacy` 扩展，不丢失旧数据。
- `LegacyBinaryExporter` 能从加载后的旧数据库、JSONL 快照或 PostgreSQL 活动批次生成可被当前
  `LoadDB()` 读取的数据库，作为二进制写入、回读和纯控制面回滚保障。
- 索引映射表记录 `local_index` 与 `content_key` 的对应关系。

## 4. 代码抽离顺序

1. 新建程序集和项目引用，不移动逻辑。
2. 把纯数据模型和常量移到 `Crystal.Shared` / `Crystal.Content`。
3. 把地图/对象/战斗逻辑移到 `Crystal.GameCore`，保持命名空间兼容或提供类型转发。
4. 把宿主、网络、数据库访问移到 `Crystal.ZoneServer`。控制台宿主已建立；数据库和内容访问仍复用旧实现。
5. 删除 WinForms 对游戏逻辑的直接依赖。

每一步都要能编译和运行旧流程。

## 5. 验证清单

- 实体数量和索引一致。
- 物品属性、价格、堆叠、绑定规则一致。
- 怪物属性、AI、掉落一致。
- 地图尺寸、阻挡、安全区、传送点一致。
- NPC 脚本可解析、可执行。
- 任务、技能、商城、配方引用完整。
- 登录、选角、进服、移动、战斗、掉落、交易冒烟通过。

## 6. 回滚

- 数据回滚：恢复 PostgreSQL 备份或切回二进制数据库。
- 内容回滚：激活上一 `release_id`。
- 代码回滚：部署上一构建。
- 客户端回滚：启动器恢复上一版本目录。
- 合区回滚：保留源区数据，按报告反向恢复。
