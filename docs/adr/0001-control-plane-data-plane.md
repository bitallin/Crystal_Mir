# 0001 控制面与数据面分离

- 状态：已接受
- 日期：2026-11-09

## 背景

当前 `Server.MirForms` 同时承担服务端运行、内容编辑和数据库管理。这个模式难以支持多版本、多区服、发布回滚、支付和审计，也会让后台操作直接阻塞游戏主循环。

## 决策

将系统拆为控制面和数据面：

- 控制面：Admin Web、Control API、内容/发布/运营/支付/审计，使用 PostgreSQL、Redis、对象存储。
- 数据面：Zone Server 运行现有游戏核心，通过 Zone Agent 接受控制。
- 两者通过 gRPC/HTTP 契约和签名内容包交互，不共享进程内状态。

## 备选方案

1. 直接在 WinForms 上增加 Web 功能：改动小，但无法解决多区服、审计和扩展问题。
2. 全部重写为微服务：成本过高，破坏现有游戏逻辑。

## 影响

- 需要新增项目、部署单元和契约。
- 区服必须支持离线运行和内容快照缓存。
- 控制面可以独立发布和扩展。
- GPL 边界更清晰。

## 重新评估条件

如果单区维护成本显著低于拆分成本，可先保留嵌入式 Agent，但控制面/数据面逻辑边界不变。
