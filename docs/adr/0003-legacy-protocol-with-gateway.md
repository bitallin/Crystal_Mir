# 0003 保留现有协议并引入边缘网关

- 状态：已接受
- 日期：2026-11-09

## 背景

现有客户端使用自定义二进制协议，`Shared/ClientPackets.cs` 和 `Shared/ServerPackets.cs` 定义了数百个包。直接重写协议会导致客户端大改，风险高。

## 决策

- 保留现有包结构和客户端兼容性。
- 在客户端与区服之间增加边缘网关，负责登录、版本校验、区服路由、限流和基础防护。
- 网关不改变包体语义，只做转发和状态编排。
- 破坏性变更通过 `protocol_version` 和兼容窗口管理。

## 备选方案

1. 重写为 HTTP/WebSocket 协议：现代化，但客户端改造量巨大。
2. 不做网关，继续单端口：简单，但无法支持多区服、合区和统一防护。

## 影响

- 网关需要理解登录/选角/进服状态机。
- 区服仍然处理游戏包，网关保持轻量。
- 需要协议回放测试和版本协商。

## 重新评估条件

如果客户端决定重写或迁移到跨平台渲染层，可重新评估协议栈，但必须保留旧客户端兼容期。
