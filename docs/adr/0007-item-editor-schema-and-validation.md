# 0007 物品编辑器 Schema 与两级校验

- 状态：已接受
- 日期：2026-11-16

## 背景

M1 已建立通用草稿实体写入、revision 乐观并发、草稿校验、发布和回滚闭环，但后台仍没有类型化内容表单。
物品是内容引用最密集的实体之一，字段数量多，且包含 `Stats.Values` 动态属性表和 70 个随机属性字节字段。
如果继续让前端自由拼接 JSON，字段类型、枚举、范围和索引一致性都只能靠人工保证。

现有完整物品模型位于 GPL 覆盖的服务端代码边界内。控制面不能链接这些程序集，也不能通过反射直接复用其类型；
同时本轮不能改变现有客户端协议、旧二进制数据库或 `Envir` 行为。

## 决策

### 1. Schema 由 Control API 手工维护并版本化

- 新增 `GET /api/v1/editor-schemas/item`，要求 `content:read`；当前只提供 `item`，其他类型返回 404。
- Schema 固定返回 `schemaVersion=1`，按基础信息、使用要求、经济与背包、行为开关、固定属性、随机属性分组。
- 字段定义包含路径、标签、类型、必填性、只读性、默认值、最小值/最大值、枚举选项和复合字段信息。
- Schema 覆盖 33 个顶层物品字段、`Stats.Values` 动态键值表和 `RandomStats` 下的 70 个字节字段。
- 枚举、flags 和固定属性键由 Control API 的手工清单维护；不引用 `Shared`、`Server` 或其他 GPL 程序集。
- Schema 版本与草稿实体的 `schemaVersion` 一致；不兼容字段变化必须提升版本并保留旧版本读取路径。

### 2. 类型化创建复用现有草稿表

- 新增 `POST /api/v1/drafts/{id}/content/item`，要求 `content:write`。
- 服务端在单个事务内读取草稿、锁定草稿行，分配该草稿内下一个 `localIndex`，覆盖请求中的 `Index`，
  生成 `item.<localIndex>` 并写入 `content_draft_entity`。
- 同一事务写入 `create` 修订并更新草稿时间戳；返回 201 和创建后的实体。
- 请求显式携带的 `Index`、`contentKey` 不参与服务端分配，避免客户端并发创建时冲突。
- 不新增数据库迁移，继续使用 ADR 0006 的 `content_draft`、`content_draft_entity` 和 `content_draft_revision`。

### 3. 保存阻断结构错误，完整性问题留给草稿校验

- `PUT` 和类型化创建在写入前执行结构校验，失败返回 400 字段错误。
- 结构校验包括：整数类型及范围、字符串、布尔值、枚举、逗号分隔 flags、`Index == localIndex`、
  `contentKey == item.<localIndex>`、`Stats.Values` 键和值类型、随机属性字节范围。
- 允许保存不完整物品；字段缺失、空名称、对象内部缺少字段等问题由草稿/发布校验报告
  `item-completeness` 或 `item-content-key`，避免编辑器无法保存进行中的草稿。
- `RandomStats` 缺失在旧内容中表示全零随机属性，发布校验视为合法；一旦出现，必须是对象且包含全部 70 个字段。
- `Stats` 出现时必须有对象类型的 `Values`；缺失 `Stats.Values` 作为完整性问题报告。
- 未知字段原样透传，避免旧数据或未来字段在编辑保存时被静默丢弃。

### 4. Web 使用 Schema 驱动表单和字段级差异

- 物品编辑抽屉从 `editor-schemas/item` 动态生成分组表单，不在前端复制字段清单。
- `Stats.Values` 使用可增删的属性行；随机属性按 70 个字段展示并限制为 0～255。
- 保存前后按字段生成差异；服务端 400 字段错误映射到对应控件，409 冲突保留当前输入并提供载入最新 revision。
- 物品列表在草稿模式下使用草稿查询接口，并支持内联选择或创建草稿。
- 只读用户只能查看 live 内容，不显示保存、删除、创建草稿和校验动作。

## 备选方案

1. 通过反射复用 `Shared` 的物品类型：会跨越 GPL 边界，且把运行时类型暴露为控制面契约，拒绝。
2. 保存时要求所有字段完整：会阻止未完成草稿和部分迁移，拒绝。
3. 在浏览器硬编码表单：字段规则与 API 校验漂移，无法为其他客户端复用，拒绝。
4. 为物品建立独立编辑表：当前草稿模型已满足 revision 和发布冻结，新增表只会扩大迁移范围，拒绝。

## 影响

- Schema 是手工维护的契约，字段变更必须同步更新 API 校验、Web 测试和参考文档。
- 保存成功不等于可发布；作者必须运行草稿校验，发布校验会再次执行完整性规则。
- 旧内容缺失 `RandomStats` 可以继续发布；编辑器首次保存该类物品时可按全零默认值补齐。
- 本轮不包含资源预览、批量导入导出、价格/属性模拟和授权/许可证处理。

## 重新评估条件

- 物品字段需要从单一 GPL 源自动生成且能通过 MIT 契约隔离。
- 需要多人同时编辑同一物品，或引入字段级协作锁。
- Schema 版本需要兼容多个客户端协议版本并支持迁移窗口。
- 批量导入导出、资源预览或引用选择器成为后续 M2 切片。
