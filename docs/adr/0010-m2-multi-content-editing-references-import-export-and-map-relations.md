# 0010 M2 多内容编辑、引用、批量导入导出与地图关系写入模型

- 状态：已接受
- 日期：2026-11-17

## 背景

ADR 0008 建立了按 `entityType` 注册的编辑器框架，ADR 0009 只把地图顶层标量元数据纳入编辑。M2 需要让版本作者在同一草稿上下文中编辑物品、怪物、地图、NPC、脚本、掉落、技能、任务、商城和配方，并处理跨实体引用、脚本派生字段、批量导入导出以及地图嵌套关系。

这些能力横跨内容身份、校验、Web 编辑器和草稿事务。如果每种类型各自实现写入、搜索和校验，会出现内容键规则不一致、保存时丢失未知字段、跨批次引用漂移以及地图投影与独立实体不一致。另一方面，现有客户端协议、内容快照格式和数据库草稿表已经稳定，本轮不能通过迁移协议来换取编辑便利。

## 决策

### 1. 注册 10 类 Schema 驱动编辑器

控制面注册 `item`、`monster`、`map`、`npc`、`script`、`drop`、`magic`、`quest`、`gameshop` 和 `recipe` 十类编辑器。Schema 继续由 MIT 控制面代码手工维护，不引用 GPL 实体类型；Web 根据 `GET /api/v1/editor-schemas/{entityType}` 动态生成表单和搜索字段。

字段类型扩展为 `number`、`array`、`reference`、`code`、`color` 和 `readonly`，并增加 `referenceType`、`nullable`、`multiline`、`minItems`、`maxItems`。新增 DTO 属性均为可选，省略时不改变既有 Schema 响应语义。

### 2. 内容身份由服务端解析

编辑器定义提供身份、规范化、引用、标签和搜索钩子。新建实体的 `localIndex` 与内容键按下表生成；客户端不能指定或改写已有内容键。

| 类型 | localIndex | 内容键 |
| --- | --- | --- |
| `item` / `monster` / `map` | 自动分配 | `<type>.<localIndex>` |
| `npc` / `quest` | 自动分配 | `<type>.<localIndex>` |
| `gameshop` | 自动分配 `GIndex` | `gameshop.<GIndex>` |
| `magic` | 用户选择 `Spell` | `magic.<Spell>` |
| `recipe` | 自动分配 | `recipe.<产出物品名>` |
| `script` | 自动分配 | `script.<规范化文件路径>` |
| `drop` | 等于 `monsterIndex` | `drop.monster.<monsterIndex>` |

旧内容键原样保留，包括配方键中的历史括号等字符。新建实体使用安全键段；保存和发布校验同时接受当前安全键与对应旧键，避免已有内容在首次编辑时被迫改名。

### 3. 统一两级校验和引用解析

保存路径统一阻断字段类型、整数范围、枚举、flags、必填引用形状、`Index`/`GIndex`/`monsterIndex` 与 `localIndex` 一致性以及内容键结构错误。草稿和发布校验再报告完整性问题、内容键不一致、重复身份和必填引用缺失。

问题码统一使用 `<type>-completeness`、`<type>-content-key`、`<type>-duplicate`、`reference-missing` 等稳定形式。保存前规范化只处理已知派生字段，例如脚本 AST、页面、行数和 SHA256，以及商城 `ItemIndex`/`Info` 的同步；Schema 之外的未知字段原样保留。

引用选择使用 `GET /api/v1/content/{entityType}/options`，按活动草稿或指定导入批次搜索目标，返回 `localIndex`、`contentKey`、名称和摘要。引用规则声明引用类型、存储方式（索引、字符串或 `$ref`）和是否必填；草稿和发布校验使用同一套解析逻辑。

### 4. 脚本源码是行为事实

脚本编辑器编辑规范化文本源码。保存和 `POST /api/v1/drafts/{id}/content/script/{localIndex}/validate` 均由服务端重新计算 AST、页面、语句块、静态引用、问题、行数、源码 SHA256 和编译哈希。Web 只读展示 AST、页面和问题，不提供语句块拖拽或独立于文本的修改。

### 5. JSONL 导入导出沿用快照实体行

草稿导入使用与内容快照一致的 JSONL 实体格式，单次请求限制 16 MiB。导入默认 `dryRun=true`；dry-run 返回逐行错误摘要但不写草稿。应用模式在单事务内按 `contentKey` upsert，冲突返回 409，并记录草稿修订和审计。

导出从活动草稿或指定导入批次生成按 `localIndex` 稳定排序的 JSONL，实体行与快照格式一致。本轮只支持 JSONL，不提供 CSV，也不直接从导入创建发布批次。

### 6. 地图关系分区写入并维护投影

传送、安全区、矿区和激活坐标作为地图实体内的数组整体替换，请求携带 `expectedRevision`。刷新点和 NPC 以独立 `respawn`、`npc` 实体为事实来源，通过行级 POST/PUT/DELETE 写入；同一事务内同步地图实体的 `Respawns`、`NPCs` 投影，避免后续发布重建时引用漂移。

写入前校验坐标非负、在地图资源尺寸内，目标地图、怪物和 NPC 脚本存在。关系读取接口同时返回地图摘要、关系数组、分页刷新点和 NPC。地图预览接口按需解析地图文件并降采样返回可走、阻挡和门格网格；不解析客户端 `.lib` 图库。

### 7. 保持存储与发布边界不变

本轮不新增数据库迁移，不改变数据库草稿表、客户端协议、快照文件格式、发布 manifest 或本地索引语义。新增接口只使用现有 `content_draft_entity`、修订和审计结构。

## 备选方案

1. 每种内容类型独立实现编辑和校验：会造成内容键、引用和问题码漂移，拒绝。
2. 新建实体也沿用所有历史内容键写法：无法保证新键的可解析性和唯一性，拒绝；改为新建安全键、旧键继续可读。
3. 地图刷新点和 NPC 只写地图内嵌数组：发布重建时没有独立事实来源，且难以按行并发编辑，拒绝。
4. 导入直接写发布批次：绕过草稿审阅和发布校验，拒绝。
5. 在 Web 本地解析脚本或地图二进制：会产生第二套行为语义并跨越许可证边界，拒绝。

## 影响

- 版本作者可以在后台完成 10 类核心内容的创建、修改、校验、发布和回滚。
- 引用缺失、重复掉落目标、重复产出配方、脚本错误和地图关系越界会在草稿/发布校验中暴露。
- 旧导入内容仍可编辑；旧内容键不需要在首次保存时迁移。
- 地图关系行写入与地图投影保持一致，发布重建不需要由 Web 额外修补引用。
- 批量导入和导出可用于离线修正与审计，但只操作草稿，不替代发布流程。
- 授权、许可证、素材合规、M3 Agent、热切换和灰度发布不在本决策范围。

## 重新评估条件

- 需要改变内容键格式或迁移旧历史键时。
- 需要增加 CSV、流式导入、超大导入任务或服务端导入批次时。
- 需要支持 NPC 语句块结构化编辑、脚本执行或脚本沙箱时。
- 需要地图关系整图大事务替换、地图文件上传或 `.lib` 资源解析时。
- 需要跨草稿、跨版本共享引用或全局内容 ID 时。
