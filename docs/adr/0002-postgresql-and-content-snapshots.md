# 0002 PostgreSQL 与内容快照

- 状态：已接受
- 日期：2026-11-09

## 背景

现有 `Server.MirDB` 是自定义二进制格式，版本 117，适合单进程读写，但不适合 Web 后台、并发编辑、审计、合区和内容发布。

## 决策

- 控制面主库使用 PostgreSQL。
- 编辑态使用关系表 + `jsonb` 保存复杂实体。
- 发布时编译为不可变内容包和签名 manifest。
- 区服运行时只读消费内容快照，不直接查询编辑表。
- 保留二进制导入/导出工具用于迁移和回滚。

## 备选方案

1. 继续使用二进制数据库：迁移成本低，但并发、查询、审计和合并能力不足。
2. 直接让区服读 PostgreSQL：实时性强，但耦合高、性能不可控、发布不可回滚。
3. 使用 MongoDB： schema 灵活，但事务、关系和审计能力不如 PostgreSQL。

## 影响

- 需要定义内容 schema 和编译流程。
- 需要处理旧数据迁移和 ID 映射。
- 区服启动依赖内容包，不依赖编辑库。
- 发布、回滚和灰度成为一等能力。

## 重新评估条件

如果内容包体积或加载时间成为瓶颈，可评估 MessagePack、分片包或本地缓存层，但不可变快照模型不变。
