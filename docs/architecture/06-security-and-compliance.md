# 安全与合规

> 最后更新：2026-11-11
> 状态：生效

## 1. 威胁模型

| 威胁 | 影响 | 主要措施 |
| --- | --- | --- |
| 管理员账号被盗 | 内容/资产/数据被篡改 | MFA、RBAC、会话短时有效、异常登录告警 |
| 内容注入 | 恶意脚本或资源 | 沙箱、白名单、签名、发布审核 |
| 补丁供应链攻击 | 客户端被植入恶意代码 | 签名 manifest、哈希、TLS、构建签名 |
| 支付欺诈 | 虚假订单/重复发货 | 验签、幂等、风控、对账 |
| DDoS/CC | 登录和区服不可用 | WAF、限流、清洗、分区隔离 |
| 作弊/协议攻击 | 经济破坏、复制物品 | 服务端权威、包校验、行为检测 |
| 数据泄露 | 账号/支付/个人信息 | 最小权限、加密、脱敏、审计 |
| 内部人风险 | 越权发物品/改数据 | 审批、限额、审计、双人复核 |

## 2. 身份与权限

### 2.1 管理端

- 支持本地账号 + 可选 OIDC/SSO。
- 管理员必须启用 MFA。
- 会话使用短时 JWT + 刷新令牌；高风险操作重新认证。
- 登录失败锁定、IP 白名单（可选）、异常地点告警。

M1 已实现本地账号、Argon2id、短时 JWT、刷新令牌轮换、登录失败锁定、RBAC、只追加审计，以及账号
停用/启用、管理员重置密码、自助改密和角色调整。停用、重置和角色变更会撤销相关会话；系统禁止停用
最后一个启用的平台管理员。MFA/OIDC、IP 白名单、账号删除和高风险操作再认证仍待实现。

### 2.2 RBAC 角色

| 角色 | 权限 |
| --- | --- |
| 平台管理员 | 系统配置、用户/角色、区服、模板 |
| 版本作者 | 内容编辑、资源上传、发布申请 |
| 发布审核 | 审核、发布、回滚 |
| GM | 在线管理、公告、补偿、封禁 |
| 财务 | 订单、对账、退款 |
| 审计 | 只读审计和导出 |

权限按“资源 + 动作”授权，例如 `content:write`、`release:publish`、`zone:merge`、`payment:refund`。

### 2.3 高风险操作

- 发布/回滚内容。
- 合区。
- 修改充值/发货。
- 批量发物品/货币。
- 删除区服/版本。

要求二次确认、审批流（可配置）、操作理由和完整审计。

## 3. API 安全

- 所有管理 API 走 TLS。
- 输入校验使用统一 schema，拒绝未知字段（按接口策略）。
- 分页、排序、过滤白名单，防止注入和全表扫描。
- 限流按用户/IP/接口维度。
- 幂等键用于发布、发货、合区、支付回调。
- 错误响应不泄露堆栈、SQL、密钥和内部路径。
- 审计日志记录请求 ID、操作者、资源、结果、耗时。

## 4. 密钥与配置

- 数据库密码、支付密钥、签名私钥放入 Vault/KMS/云密钥管理。
- 仓库只保留示例配置，不提交真实密钥。
- 签名私钥与发布服务隔离，最好使用硬件/托管 KMS 签名。
- 配置变更需要审计；敏感配置读取需要授权。
- 日志脱敏：密码、令牌、支付账号、身份证、IP 按策略处理。

## 5. 内容与脚本沙箱

- 脚本只能调用白名单 API。
- 限制执行时间、内存、循环次数、递归深度、输出大小。
- 禁止文件系统、网络、进程、反射和任意程序集加载。
- 脚本编译在隔离 Worker 中执行，失败不影响控制面。
- 发布前做静态检查和动态冒烟测试。
- 运行期异常隔离到单个脚本/活动，不能拖垮主循环。

## 6. 补丁与供应链

- 所有发布包使用 Ed25519 或等效算法签名；当前内容快照使用 ECDSA P-256 + SHA-256，见 `adr/0005-content-signature-format.md`。
- 客户端只信任内置公钥对应的签名。
- manifest 有过期时间和最低版本，防降级。
- 构建产物可追溯：提交哈希、构建号、依赖清单、SBOM。
- CI 使用最小权限令牌，发布密钥不进入构建日志。
- 依赖漏洞扫描和许可证扫描进入 CI。

## 7. 游戏安全

- 服务端权威：移动、战斗、掉落、交易、支付发货都以服务端为准。
- 包长度、字段范围、状态机校验；异常包计入风控。
- 登录/注册/找回密码限流。
- 交易、邮件、拍卖、仓库做复制和刷物品检测。
- GM 命令与普通协议分离，强认证和审计。
- 客户端完整性校验和版本校验只作为辅助，不替代服务端校验。

## 8. 数据保护

- 密码使用 Argon2id/bcrypt，禁止明文和可逆加密。
- 个人信息最小化收集，明确保留期限。
- 备份加密，恢复需要授权。
- 导出数据脱敏并记录审计。
- 删除账号/角色遵循保留和合规策略。

## 9. 许可证边界

| 代码 | 许可证 | 约束 |
| --- | --- | --- |
| `Client/`、`Shared/` | MIT | 可闭源分发客户端，保留版权许可 |
| `Server/`、`Server.MirForms/`、`Tests/` | GPL-3.0-only | 分发服务端二进制需提供完整对应源码 |
| 第三方依赖/素材 | 各自许可 | 单独审查和记录 |

实施要求：

- 控制面不链接 GPL 服务端代码，跨边界只使用 MIT 契约。
- 如果分发区服二进制，准备对应的 GPL 源码归档和获取方式。
- 素材必须记录来源和授权；没有授权的传奇官方素材不得进入商业分发。
- 许可证变更必须走 ADR，并由法律/合规确认。

详见 `adr/0004-gpl-boundary.md`。

## 10. 审计

审计事件至少包含：

```text
event_id, occurred_at, actor_id, actor_ip, action, resource_type,
resource_id, before_hash, after_hash, request_id, result, reason
```

审计日志只追加，定期归档到只读存储；管理员不能删除自己的审计记录。
