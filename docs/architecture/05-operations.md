# 运营与区服生命周期

> 最后更新：2026-11-09
> 状态：生效

## 1. 区服生命周期

```text
创建 -> 配置 -> 部署 -> 预热 -> 开放 -> 运行 -> 维护 -> 合并/关闭 -> 归档
```

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| `created` | 已创建未部署 | 修改配置、绑定模板 |
| `deploying` | 正在部署 | 查看日志、取消 |
| `warming` | 预热中 | 健康检查、切换内容版本 |
| `open` | 对外开放 | 玩家进入、GM 操作 |
| `maintenance` | 维护中 | 禁止新登录、数据迁移 |
| `merging` | 合区中 | 冻结写入、只读查询 |
| `closed` | 已关闭 | 导出、归档、销毁 |
| `archived` | 已归档 | 只读查询 |

区服表见 `03-data-and-content.md`。

## 2. 开区

### 2.1 开区流程

```text
选择模板 -> 填写区服信息 -> 分配端口/资源 -> 生成配置
-> 创建区服数据库/schema -> 启动 Zone Server
-> Agent 注册 -> 健康检查 -> 拉取内容包
-> 预热地图/脚本 -> 公告 -> 开放登录
```

### 2.2 模板

模板包含：

- 内容版本或内容版本范围。
- 区服配置默认值（经验倍率、掉率、开放时间、地图组）。
- 数据库连接模板（不包含明文密码）。
- 网络端口范围、容量、限流。
- 监控策略和告警规则。

模板变更不影响已创建区服；新配置通过版本化模板发布。

### 2.3 健康门禁

开放前必须通过：

- Agent 心跳正常。
- 内容包哈希与签名校验通过。
- 地图加载完成，关键 NPC/传送点存在。
- 数据库连接和迁移版本正确。
- 登录/选角/进服冒烟测试通过。
- Tick 延迟在阈值内。

## 3. 合区

合区是当前架构中风险最高的操作，必须在设计初期考虑 ID 和数据结构。

### 3.1 前置条件

- 源区和目标区内容 schema 兼容，或完成内容迁移。
- 两个区服进入 `merging`，冻结写入。
- 完成全量备份和恢复演练。
- 角色名、公会名、账号冲突有明确策略。
- 支付/发货队列已清空或可重放。

### 3.2 合区阶段

```text
1. 预检：schema、内容版本、ID 冲突、名称冲突、容量
2. 冻结：禁止登录和写操作，踢下线或只读
3. 备份：数据库、对象存储、区服配置
4. 映射：生成 merge_id_map（account/character/guild/item/...）
5. 迁移：按数据域合并，处理冲突
6. 校验：数量、引用、余额、背包、邮件、拍卖、攻城
7. 切换：更新区服入口和配置
8. 解冻：开放登录，观察指标
9. 回滚窗口：保留源数据，超时后归档
```

### 3.3 冲突策略

| 冲突 | 默认策略 |
| --- | --- |
| 账号重复 | 按登录身份合并；无法确认时保留并人工处理 |
| 角色名重复 | 目标区保留，源区角色获得改名券或后缀 |
| 公会名重复 | 目标区保留，源区公会改名或合并申请 |
| 物品 ID 重复 | 使用全局 ID 重新分配，不改协议索引 |
| 邮件/拍卖 | 迁移到目标区并重新计算过期时间 |
| 攻城/占领 | 保留目标区状态，源区记录审计 |
| 排行榜 | 合区后重算 |

### 3.4 校验报告

合区前后生成机器可读报告：

- 账号/角色/公会数量对比。
- 每个角色资产总量和关键字段哈希。
- 邮件、拍卖、任务、技能数量。
- 金币/货币余额汇总。
- 引用完整性错误。
- 名称冲突和改名清单。

任何 `error` 阻止切换。

## 4. 支付与发货

### 4.1 订单状态机

```text
created -> pending -> paid -> delivering -> delivered
                    -> failed
         -> cancelled
         -> refunding -> refunded
```

### 4.2 关键要求

- 支付回调必须验签、幂等、防重放。
- 订单金额以服务端商品配置为准，不能信任客户端。
- 发货通过 Outbox + Zone 命令，按 `order_id` 幂等。
- 账本只追加，退款使用反向分录。
- 每日自动对账，差异告警并生成人工处理任务。
- 支付密钥放在密钥管理系统，不写入仓库和日志。

### 4.3 发货流程

```text
paid 回调 -> 更新订单 -> 写账本 -> 写 delivery_outbox
-> Worker 调用 Zone Agent -> Zone 校验并发放
-> 返回 delivery_id -> 标记 delivered
-> 超时重试，超过阈值转人工
```

## 5. GM 工具

第一批 GM 能力：

- 在线列表、踢人、封禁/解封、禁言。
- 公告、私聊、邮件补偿。
- 发放物品/货币（必须审计和限额）。
- 传送、召唤、刷怪、清理怪物。
- 重载内容、切换内容版本、回滚。
- 查看区服指标、日志、Tick 延迟。
- 查询订单和发货状态。

所有 GM 操作记录操作者、目标、参数、结果、IP、时间；高风险操作需要二次确认或双人审批。

## 6. 监控

### 6.1 指标

| 类别 | 指标 |
| --- | --- |
| 区服 | 在线人数、连接数、Tick 延迟、对象数、地图数 |
| 网络 | 包速率、丢包/超时、登录成功率、断线率 |
| 内容 | 发布状态、热重载耗时、失败率、内容版本分布 |
| 支付 | 订单量、支付成功率、发货延迟、对账差异 |
| 系统 | CPU、内存、GC、线程、磁盘、网络 |
| 安全 | 登录失败、封禁、异常包、WAF 拦截 |

### 6.2 告警

- Tick 延迟持续超阈值。
- 区服心跳丢失。
- 发布/热重载失败。
- 支付回调失败或对账差异。
- 数据库连接池耗尽、磁盘不足。
- 客户端更新成功率骤降。

## 7. 备份与灾难恢复

- PostgreSQL：每日全量 + 持续 WAL 归档，支持 PITR。
- 对象存储：版本控制 + 跨区域复制（按需）。
- 区服：停机快照、配置导出、内容版本记录。
- 恢复演练：至少每季度一次，记录 RPO/RTO。
- 合区和支付操作前强制备份。

## 8. SLO 建议

| 服务 | 目标 |
| --- | --- |
| 管理 API | 99.9% 可用，P95 < 300ms |
| 登录/网关 | 99.9% 可用，登录 P95 < 2s |
| 区服 | 按版本设定，Tick P99 可观测 |
| 内容发布 | 发布任务可重试，失败可回滚 |
| 支付发货 | 99.9% 在 60s 内完成，超时告警 |
