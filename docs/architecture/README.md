> 最后更新：2026-11-09
> 状态：生效

## 1. 架构目标

把当前的单区 Crystal 服务端演进为“通用传奇引擎平台”，支持：

- 后台可视化制作版本内容。
- 内容版本化发布、灰度、回滚。
- 客户端资源和服务端内容热更新。
- 多区服开区、合区、支付、GM 和监控。
- 第三方基于模板快速创建自己的版本并部署。

## 2. 非目标

- 不在第一阶段重写客户端渲染层。
- 不在第一阶段实现任意 UI 拖拽布局编辑器。
- 不在第一阶段做多租户计费平台。
- 不把现有 `Envir`/`Map` 一次性重写为全新引擎。

## 3. 设计原则

- 控制面与数据面分离：编辑、发布、运营与实时游戏世界解耦。
- 内容不可变：每次发布生成不可变快照，运行区服只读消费。
- 先兼容再演进：保留现有客户端协议和二进制数据库导入能力。
- 逻辑数据化：把硬编码的 AI、技能、活动、UI 参数逐步转为配置或脚本。
- 单一事实来源：内容编辑在关系型数据库，运行时消费编译后的内容包。
- 可回滚：数据迁移、内容发布、客户端补丁和合区都必须有回滚路径。
- 可观测：每个关键流程有日志、指标、追踪和审计。

## 6. 当前实现与目标架构

当前实现是单进程、单区、二进制数据库、WinForms 编辑器、手工补丁工具。目标架构不是替换它们，而是在其外围增加控制面、内容发布、运营和数据能力，并把游戏核心逐步抽成可独立托管的区服。

任何“后台可配置一切”的需求，先判断属于以下哪一类：

- 纯数据：直接 CRUD，进入内容包。
- 有限枚举：数据 + 校验，保留代码分支。
- 行为逻辑：脚本或插件，必须有沙箱和版本。
- 客户端表现：资源 + 参数 + 数据驱动 UI，必要时才改客户端代码。
